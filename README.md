# STM32H503CBT6 template

## Overview

This is the Waterloo Rocketry template for STM32H503CBT6 projects. Startup code, headers, HAL, etc. are generated by STM32CubeMX.
Build, flash, and debug are performed using CMake through the STM32Cube VS Code extension.

## Getting started

### Create new repo using template

1. Go to https://github.com/waterloo-rocketry/stm32h503_template/ and click in the top right `Use this template > Create a new repository`.

2. Disable `Include all branches`, make the owner the `waterloo-rocketry` organization, give it a descriptive but concise name (starting with the prefix `cansw_` if it's part of the CAN bus aboard the rocket), and make the visibility `Public`. Then click `Create repository`.

3. Clone the repository to your computer. You can get the Git URL by opening your repo in GitHub, going to the `Code` tab, and clicking the green `Code` button, which will show the URL in the `Clone` section. Copy this URL, then on your computer (with Git installed), open a terminal and run:

   ```
   $ git clone <the Git url you copied>
   ```

4. Change directory into your repo by running:

   ```
   $ cd <repo folder name>
   ```

5. Initialize the rocketlib submodule by running:

   ```
   $ git submodule update --init --recursive
   ```

### Open in VS Code and install the STM32CubeIDE extension

1. Install and open VS Code.

2. Install the extension pack "STM32CubeIDE for Visual Studio Code". Note there are a bunch of similarly named extensions bundled by the main pack, so make sure you specifically get the **extension pack** containing a bunch of extensions.

3. Wait for a pop-up in the bottom right that says something like `About to install following cube bundle(s): ...` and click `Yes`. Wait for all of the installs to complete. More of the same prompts may appear; click `Yes` for all of them.

4. Close and reopen VS Code in the root folder of your repo.

### Configure project CMakeLists.txt

1. Open the [top-level CMakeLists.txt](./CMakeLists.txt).

2. Find the call to set `CMAKE_PROJECT_NAME` and change it to a name for your project.

3. Find the `target_compile_definitions` call and uncomment the lines setting `BOARD_TYPE_UNIQUE_ID` and `BOARD_INST_UNIQUE_ID`. Replace the values with the correct rocketlib board type and instance. Possible values are defined in [packet_format.h](./third_party/rocketlib/can_message/packet_format.h).

4. Find the `target_link_libraries` call and add the desired rocketlib source folders by linking libraries of the form `rocketlib::<folder name to include>`. If you only want to use headers you can just link `rocketlib::headers`.

### Build and flash using CMake

1. Open the `CMake` extension tab.

2. Under `Configure`, select a configure preset.

3. Build the firmware.

4. Open the `Run And Debug` tab.

5. Debug using the `STM32Cube: Launch ST-Link GDB Server` configuration.

6. If you just want to flash, once the programming is finished you can detach the GDB server and power cycle the board.

### Configure peripherals and generate drivers using STM32CubeMX

1. Install [STM32CubeMX](https://www.st.com/en/development-tools/stm32cubemx.html) (not CubeMX2).

2. Rename the `third_party/stm32cubemx/stm32h503_template.ioc` file to something more specific to your project.

3. Open the `.ioc` file with STM32CubeMX, configure the project as desired, save the `.ioc` file, and click `GENERATE CODE` to update the code.

### Develop code

The main entry point for your firmware should be `fwmain()` in `src/fwmain.c`. Your application code should go in `src/` and headers in `inc/`.

The actual main function in `third_party/stm32cubemx/Core/Src/main.c` just calls `fwmain()` after the CubeMX-generated initialization code runs. If you need to, you can change the CubeMX `main.c` by modifying code in between the pairs of `USER CODE BEGIN` and `USER CODE END` comments; anything outside of these sections will be overwritten by CubeMX upon regenerating the code.

### Format code

From the CMake Tools extension, run the `format-check` and `format` CMake targets to respectively check the formatting of and format the code. In order to do this you must install `clang-format` from [LLVM](https://github.com/llvm/llvm-project/releases/)'s `clang-tools` and add it to your PATH. If it can't find it in your PATH despite being added, try restarting VS Code.
